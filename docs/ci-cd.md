# DFCS CI/CD

The workflow `.github/workflows/cicd.yml` runs on pushes, pull requests, and manual dispatches. It implements an initial subset of SRS section 12 (FR-070, NFR-010, NFR-016, NFR-017), not the complete release pipeline.

1. **Build and test:** GitHub-hosted Windows runner; checksum-verified WinLibs GCC, CMake and Ninja from `tools/tool-versions.cmake`; configure, build and test with `host-strict`. JUnit, CTest logs and source/tool provenance are retained as artifacts for 14 days. Build or test failures block subsequent stages.
2. **HEX packaging:** explicitly BLOCKED pending an STM32 executable target, linker/startup configuration and pinned Arm toolchain (ST-073). The reporting job succeeds so security scans can run, but no HEX is produced and the workflow is not a successful firmware release. Do not convert host test executables or the static library to HEX. Future packaging must cross-build an STM32 ELF, run the pinned Arm `objcopy -O ihex`, and publish the HEX with provenance only after required gates pass.
3. **Security scans:** checksum-verified Gitleaks scans checked-out Git history with redacted SARIF; any detected secret fails the job. CodeQL analyzes C++ without compilation using `security-extended`; findings with CodeQL security severity at least 9.0 (critical) fail the job. Reports are retained as artifacts, not uploaded to GitHub code scanning. High and lower severity findings require review; this is not a complete static-analysis or compliance gate. Private repositories need GitHub Code Security entitlement for CodeQL; no silent fallback is configured. Fork pull requests use only read-only checkout credentials and do not receive AWS secrets.
4. **AWS deployment:** disabled with an unconditional false job condition. No AWS credentials, authentication, provisioning or deployment is implemented. Enabling deployment requires a separate approved change, real firmware artifacts and release approvals. Firmware flashing and flight authorization must never be automated.

GitHub Actions are pinned to immutable commits. Build/scanner versions and archive checksums, including the CodeQL bundle and query packs, live in the tool manifest. Hosted OS images are maintained by GitHub, so the workflow does not claim bit-for-bit reproducibility. Update action commits deliberately alongside tool pins.

Remaining SRS section 12 gates: agreed formatting/static-analysis tooling (ST-003), STM32 cross-build, coverage, integration and SITL. Configure the `Build and test` and `Security scans` checks as required branch checks. Passing this POC workflow does not establish certification or flightworthiness (NFR-017).
